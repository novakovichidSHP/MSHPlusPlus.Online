# Спайк Asyncify — интерактивный ввод (доказано)

> Проверено руками в браузере 2026-06-11 на локальной сборке emception (`emc-demo`, same-origin).
> Вопрос: можно ли в нашей статической модели (без бэкенда, без COOP/COEP) сделать **настоящий
> интерактивный ввод** — чтобы `std::cin` приостанавливал программу и ждал ввод пользователя.
> **Ответ: да, через Asyncify.** Цена — медленная компиляция, поэтому интерактив = opt-in.

## Контекст: почему это вопрос
В WASM программа не может «зависнуть и ждать» ввод синхронно. Нужно усыпить выполнение и
возобновить позже. Два механизма:
- **Asyncify** — флаг компиляции `-sASYNCIFY` (binaryen инструментирует код, чтобы стек можно было
  свернуть/развернуть). **Не требует никаких заголовков** → работает на голом GitHub Pages.
- **SharedArrayBuffer + Atomics.wait** — требует заголовков **COOP/COEP**. Сервера у нас нет, поэтому
  только окольно через Service Worker-шим (coi-serviceworker). Тяжелее по ограничениям. Не для MVP.

→ Выбран **Asyncify**: чистый флаг, мы сами компилируем в браузере, инфраструктура не нужна.

## Шаг A — Asyncify компилируется и приостанавливает/возобновляет ✅
Программа: `cout "A"` → `emscripten_sleep(80)` → `cout "B"`.
Флаги: `em++ -O2 -fexceptions -sASYNCIFY -sSINGLE_FILE=1 -sMODULARIZE=1 -sEXPORT_NAME=… -sEXIT_RUNTIME=1`.
- Результат: `rc=0`, вывод `A` → (реальный зазор) → `B`, exit 0.
- **Важно:** с `EXIT_RUNTIME` + Asyncify промис фабрики возвращается **после init, не дожидаясь main**.
  Завершение программы ловим через `Module.onExit/quit`, а не через `await factory()`.

## Шаг B — настоящий интерактивный `std::cin` ✅✅
`cin` приостанавливает программу и ждёт ввод, который приходит асинхронно (с задержкой).

Механизм (без tty-возни, чисто и переносимо):
1. JS-библиотека (`--js-library`) с async-импортом:
   ```js
   mergeInto(LibraryManager.library, {
     async_get_char__deps: ['$Asyncify'],
     async_get_char: function(){ return Asyncify.handleAsync(function(){ return Module.__readByte(); }); }
   });
   ```
2. В C++ — кастомный `streambuf`, гоняющий `cin` через этот импорт:
   ```cpp
   extern "C" int async_get_char();
   struct AsyncBuf : std::streambuf {
     char c;
     int underflow() override { int r=async_get_char(); if(r<0) return EOF;
       c=(char)r; setg(&c,&c,&c+1); return (unsigned char)c; }
   };
   int main(){ static AsyncBuf b; std::cin.rdbuf(&b); /* cin как обычно */ }
   ```
3. JS отдаёт байты с задержкой → `Module.__readByte()` возвращает `Promise<int>` (или -1 = EOF).

- Команда: `em++ … -sASYNCIFY --js-library /working/inlib.js … b.cpp -o b.js`.
- Результат: `Q` напечатано на 32 мс, программа сразу дёрнула чтение и **повисла**; `GOT 42` появилось
  только на ~2837 мс — ровно когда подвезли отложенный ввод. exit 0. Программа реально **спала**
  (Asyncify свернул стек), а не крутила busy-wait.

## Цена Asyncify (ключ к дизайну)
| Метрика | Обычная сборка | Asyncify |
|---|---|---|
| Время компиляции | ~3–4 с | **~16–20 с** (не разовый разогрев — каждый раз) |
| Размер модуля | ~309 КБ | ~538 КБ |

Asyncify по умолчанию инструментирует **все** функции → отсюда ×4–5 по времени и рост бинаря.
Сузить (`-sASYNCIFY_ONLY/ADD/REMOVE`) сложно: пути `std::cin` тянут глубокий iostream.

## Решение по stdin (снимает развилку)
- **Batch — дефолт.** Поле «Ввод» (модель `./prog < input.txt`). Быстрая сборка (~4 с), покрывает
  большинство учебных/олимпиадных задач. Доказано в F0/F1.
- **Интерактив — opt-in** (тумблер «интерактивный ввод», по умолчанию выкл). Включён → компилируем с
  `-sASYNCIFY`, ввод запрашивается **вживую в консоли** — ровно как в исходной Python-версии (R1!).
  Пользователь осознанно платит медленной сборкой за интерактив.
- **Будущее (зрелая фаза):** JSPI (JS Promise Integration) — замена Asyncify почти без накладных,
  но требует стабильной поддержки в браузере; пока экспериментально → не для MVP.

## Влияние на cpp-runtime API (F1)
- `compile(files, { interactive })`: при `interactive` добавляем `-sASYNCIFY` и линкуем `inlib.js`
  (генерируем на лету), оборачиваем `cin` кастомным `streambuf` (инжектим прелюдию или отдельный .cpp).
- `exec-worker`: для интерактива `__readByte` отдаёт байты не из готового буфера, а ждёт ввод из
  консоли (мост к существующему UX интерактивной консоли). Завершение — по `onExit/quit`.
- Для batch — текущая синхронная модель `Module.stdin` (уже работает).
